# Liste de tâches et sélecteur de projet — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une liste de tâches du jour dont la tâche du haut pilote le projet et l'activité du compteur, un choix (projet + activité) partagé entre appareils, et un écran principal avec sélecteur de projet et gros bouton ▶.

**Architecture:** Le serveur (`server/core.js`) porte toutes les règles : table `tasks`, réglages `choice_project` / `choice_type`, action `select`, actions sur les tâches, et la règle « la tâche du haut a changé → elle devient le choix, avec bascule si le compteur tourne », le tout dans une seule entrée du journal `ops` pour que l'annulation défasse l'ensemble. Le client (`web/logic.js`) rejoue les mêmes règles en local pour le hors ligne ; `web/app.js` affiche l'écran principal et le panneau Tâches. Les sauvegardes prennent `tasks` et figent les tâches de chaque jour de travail.

**Tech Stack:** Cloudflare Workers + D1 (SQLite), JavaScript sans framework, Node 24 (`node:test`, `node:sqlite`), Electron 44 pour la mini-fenêtre, `tools/e2e.js` (Chrome sans écran).

**Spec:** `docs/specs/2026-10-08-taches-design.md`

## Global Constraints

- Le widget Android ne change pas.
- Journée de travail de 6 h à 6 h, fuseau `Europe/Paris` (`workDayKey`, `localTime`, `workDayEnd` de `server/tz.js`).
- Description de tâche : 1 à 200 caractères après `trim`, aucun caractère de contrôle (`/[\u0000-\u001F\u007F]/`).
- Une tâche a un projet existant et une activité connue **autre que Pause**.
- Toute écriture passe par le journal `ops` (annulable d'un bloc), accepte l'heure du tap hors ligne (`actionTime(ctx)`), et est idempotente.
- Offre gratuite Cloudflare : 10 ms de calcul et 50 requêtes D1 par appel ; figer un jour coûte 3 instructions → `FREEZE_DAYS_PER_RUN = 14`.
- Identifiants en anglais ; commentaires et textes en français, apostrophe typographique ’.
- Aucune dépendance nouvelle. Le dépôt est public : aucune donnée réelle dedans.
- Un compteur oublié (plus de 24 h) ne bloque jamais une action sur les tâches : la bascule est alors sautée, seul le choix change.

## Review Focus

1. Cocher la tâche du haut pendant une **pause** : la pause doit continuer, seul le choix change ; Reprendre part ensuite sur la nouvelle tâche. → tâche 3 (serveur) et tâche 5 (client).
2. **Annuler** une coche qui a basculé le compteur : la tâche, la session fermée, la session ouverte et le choix reviennent exactement. → tâche 3.
3. Une action rejouée hors ligne (même `id`, ou état déjà atteint) ne doit pas re-basculer ni ouvrir une seconde session. → tâche 3.
4. Un ancien état en cache (sans `tasks` ni `choice`) ne doit rien casser à l'affichage. → tâche 5.
5. Une journée avec des tâches cochées mais aucune session doit quand même être figée. → tâche 4.

### Task 1: Journal généralisé et tables `tasks` / `archive_tasks`

**Files:**
- Modify: `server/schema.sql`, `server/core.js` (section `// ---- Journal ----` et `undo`)
- Test: `tests/server-schema.test.mjs`, `tests/server-undo.test.mjs`

**Interfaces:**
- Produces:
  - Table `tasks (id TEXT PRIMARY KEY, description TEXT NOT NULL, project TEXT NOT NULL, type TEXT NOT NULL, position INTEGER NOT NULL, done_day TEXT, started_ms INTEGER, done_ms INTEGER, source TEXT NOT NULL, created_ms INTEGER NOT NULL, touched_ms INTEGER NOT NULL, deleted_ms INTEGER)`, `CHECK ((done_ms IS NULL) = (done_day IS NULL))`, index `tasks_list ON tasks (deleted_ms, done_ms, position)` et `tasks_done_day ON tasks (done_day)`. `done_day` = jour de travail de la coche (aaaa-mm-jj).
  - Table `archive_tasks (archived_day TEXT NOT NULL, <mêmes colonnes que tasks, même ordre>, PRIMARY KEY (archived_day, id))` + triggers `archive_tasks_no_update` / `archive_tasks_no_delete` (`RAISE(ABORT, 'archive figée')`), comme `archive_entries`.
  - `export const TASK_COLUMNS = ['id','description','project','type','position','done_day','started_ms','done_ms','source','created_ms','touched_ms','deleted_ms']`.
  - `plain(row, table = 'entries')` : colonnes de la table (`entries` → `ENTRY_COLUMNS`, `tasks` → `TASK_COLUMNS`, `settings` → `['key','value']`).
  - `change(before, after, table = 'entries')` → `{ table, key, before, after }` avec `key` = `id` (entries, tasks) ou `key` (settings).
  - `writeRow(table, key, row)` gère aussi `tasks` (upsert sur `id`) et `settings` (upsert `key`/`value` ; `row === null` → `DELETE FROM settings WHERE key = ?`).
  - `readRow(db, table, key)` : la ligne actuelle au format `plain` (projects : `{name, position}`).
  - `undo` : pour une ligne **créée** par l'action (`before === null`) : `entries` et `tasks` → marquée supprimée (`deleted_ms`), `settings` et `projects` → retirée. Sinon remise à `before`. Vérification « la ligne n'a pas changé depuis » pour toutes les tables via `readRow` + `sameRow`.

### Task 2: Le choix partagé (`select`, `start`, `status.choice`)

**Files:**
- Modify: `server/core.js`
- Test: `tests/server-core.test.mjs`

**Interfaces:**
- Consumes: `change(..., 'settings')`, `writeRow('settings', …)` (tâche 1).
- Produces:
  - `async function readChoice(db, cfg, run, lastRow, projects)` → `{ project, type }` : `cfg.choice_project`/`cfg.choice_type` s'ils existent et que le projet existe encore ; sinon le compteur en cours hors pause ; sinon `last` ; sinon le premier projet ; type par défaut `Misc`.
  - `function choiceChanges(cfg, project, type)` → liste de `change(…, 'settings')` pour `choice_project` / `choice_type` qui diffèrent (vide si rien ne change).
  - `async function switchTo(ctx, run, project, type, at)` → changes d'une bascule (ferme `run` à `at`, ouvre une session `{ id: crypto.randomUUID(), project, type, start: at }`) ; `[]` si `run` est absent, en pause, déjà sur ce projet et cette activité, ou si la bascule dépasserait 24 h (compteur oublié).

  - Action `select { project?, type? }` : valide (`requireProject`, `requireType`, refuse `Pause` : « Pause n’est pas une activité à choisir. ») ; le choix visé = choix actuel complété par les paramètres ; changes = `choiceChanges` + `switchTo` (compteur en marche hors pause) ; `commit(ctx, 'select', 'Choix <projet> · <activité>', changes)` ; rien si aucun changement.
  - `start` : ajoute au même commit les `choiceChanges` vers le projet et l'activité lancés, **sauf** si l'activité est Pause.
  - Ajouter `select` à `WRITE_ACTIONS`.

### Task 3: Actions sur les tâches et règle de la tâche du haut

**Files:**
- Modify: `server/core.js`
- Test: `tests/server-tasks.test.mjs` (nouveau)

**Interfaces:**
- Consumes: tâches 1 et 2 (`switchTo`, `choiceChanges`, `readChoice`, journal).
- Produces:
  - `status.tasks` : d'abord les tâches à faire (non supprimées, `done_ms` nul) triées par `position` puis `created_ms` ; puis les faites dont `done_ms >= localTime(workDayKey(now), 6)`, triées par `done_ms`. Format : `{ id, description, project, type, position, done: iso|null, started: iso|null }`.
  - Actions `addTask { id, description, project?, type? }`, `editTask { id, description?, project?, type? }`, `deleteTask { id }`, `moveTask { id, before }` (`before` : id d'une tâche à faire, ou `null` = à la fin), `checkTask { id }`, `uncheckTask { id }` — ajoutées à `WRITE_ACTIONS`.
  - Fonction interne `async function withTopRule(ctx, action, summary, taskChanges)` : lit les tâches à faire, calcule la tâche du haut **avant** et **après** application de `taskChanges` (en mémoire), et si elle a changé (autre `id`, ou même `id` avec projet ou activité différents) et qu'il en existe une, ajoute `choiceChanges` vers son projet/activité et `switchTo` à `actionTime(ctx)` ; puis un seul `commit`. Une liste devenue vide n'ajoute rien.
  - Règles :
    - `addTask` : description validée (1–200, sans contrôle), projet/activité par défaut = le choix (`readChoice`) ; `position` = max des positions des tâches à faire + 1 (1 si aucune) ; `source(ctx)`. Même `id` déjà présent → rien.
    - `editTask` : tâche non supprimée ; rien si rien ne change ; `touched_ms`.
    - `deleteTask` : suppression douce ; déjà supprimée → rien.
    - `moveTask` : la tâche doit être à faire ; nouvel ordre = liste à faire sans elle, insérée avant `before` (ou à la fin) ; réécrit `position` = 1..n pour les seules lignes dont la position change ; `before` inconnu ou = `id` → invalid ; rien si l'ordre ne change pas.
    - `checkTask` : tâche à faire ; `at = actionTime(ctx)` ; `done_day = workDayKey(at)` ; `started_ms` = le plus grand `done_ms` des autres tâches non supprimées avec `done_day` égal et `done_ms <= at`, sinon `localTime(done_day, 6)` ; déjà cochée → rien.
    - `uncheckTask` : vide `done_ms`, `done_day`, `started_ms` ; garde `position` ; pas cochée → rien.
  - Messages d'erreur en français, dans le style existant (« Tâche introuvable. », « Description vide. », « Description trop longue (200 caractères max). », « La description contient un caractère de contrôle interdit. »).

- [ ] **Step 1: tests d'abord** (`tests/server-tasks.test.mjs`, harnais `makeEnv`, horloge `clock`) :
  - `addTask` sur liste vide, compteur arrêté : le choix devient le projet/activité de la tâche ; aucune session.
  - `addTask` défaut = le choix ; deuxième `addTask` ne change pas la tâche du haut → choix inchangé.
  - Compteur en marche Fluffy·Dev, liste [A: Studio·Social, B: Fluffy·Art] : `checkTask A` → session Studio·Social fermée et Fluffy·Art ouverte à la même seconde ; A a `done`, `started` = 6 h du jour ; choix Fluffy·Art.
  - Deuxième coche le même jour : `started` = `done` de la précédente.
  - Coche à 05:30 : `done_day` = la veille ; `started` = 6 h de la veille si première.
  - En pause : `checkTask` → la pause continue, choix = tâche suivante.
  - **Choix manuel respecté** : après une coche qui met Fluffy·Art, `select { project: 'Studio' }` ; puis `editTask` d'une tâche qui n'est pas en haut → choix toujours Studio.
  - `editTask` de la tâche du haut (activité changée) → le choix suit et le compteur bascule.
  - `moveTask` qui met B en haut → bascule sur B ; `moveTask` sans changement → aucune entrée `ops`.
  - `deleteTask` de la tâche du haut → la suivante s'applique ; suppression de la dernière → rien ne change.
  - `uncheckTask` : la tâche revient à sa place ; si elle redevient en haut, elle s'applique.
  - **Annulation** : `undo` d'une coche avec bascule remet la tâche, les deux sessions et le choix (comparer les lignes avant/après).
  - **Idempotence / hors ligne** : rejouer `checkTask` (même id) → aucune nouvelle entrée `ops`, aucune session en plus ; `checkTask` avec `offline: true, clientTime` 10 min plus tôt → la bascule a lieu à cette heure.
  - Compteur oublié (> 24 h) : `checkTask` réussit, pas de bascule, choix mis à jour.
  - Validation : description vide, 201 caractères, `\u0000`, projet inconnu, activité Pause → invalid.
  - `status.tasks` : à faire puis faites du jour ; une tâche cochée hier avant 6 h n'apparaît plus ; elle est toujours en base.
